03 NLB distributes traffic

Inside the traffic path

A Network Load Balancer works at Layer 4. It does not read HTTP — it accepts a TCP connection on the listener and hands the whole flow to one healthy target.

  1. Stage 1

    Client

    A browser or curl resolves the NLB DNS name and opens a TCP connection.

    TCP:80

  3. Stage 2

    NLB listener

    The listener accepts the connection and selects a target with a flow hash.

    TCP:80

  5. Stage 3

    Target group

    Holds the registered instances. Only targets passing the health check are eligible.

    HealthTCP:80

  7. Stage 4

    Healthy EC2

    Apache2 on Ubuntu 24.04 answers the request and the response returns over the same flow.

    Apache2:80

Layer

L4 · TCP

Routing decisions use connection data, not URL paths or headers.

Target selection

Flow hash

Protocol, source/destination IP and port, and TCP sequence number pick the target for each new flow.

Client IP

Preserved

With instance targets, EC2 sees the real client address — which is why its security group must allow port 80.

Cross-zone

Off by default

Each NLB node routes to targets in its own AZ unless cross-zone load balancing is turned on.

      06 Multi-AZ architecture

      Architecture blueprint

      The full network drawing: one VPC, two public subnets in two Availability Zones, an NLB with a node in each zone, and an Auto Scaling Group that spans both.

      Availability Zone 1

      10.0.1.0/24

      Public subnet · route 0.0.0.0/0 → IGW

      • EC2-01 · baseline
      • EC2-03 · scale-out
      • NLB node (AZ-1)

      Availability Zone 2

      10.0.2.0/24

      Public subnet · route 0.0.0.0/0 → IGW

      • EC2-02 · baseline
      • EC2-04 · scale-out
      • NLB node (AZ-2)

      Why two zones

      Instances are distributed across multiple Availability Zones to improve availability.

      If one zone has a problem, the NLB stops sending traffic to its unhealthy targets and the Auto Scaling Group launches replacements to restore the minimum of two.

      08 Deployment

      Build → Deploy → Scale

      Ten steps in the AWS console, in the order they depend on each other. Every resource ID is a placeholder until you create it.

      1. 01

        Create VPC

        VPC 10.0.0.0/16 named p5-vpc. Attach an Internet Gateway and add a route table with 0.0.0.0/0 → IGW.

        VPC · Internet Gateway · Route table

      2. 02

        Create subnets

        Public subnet 1 10.0.1.0/24 in AZ-1, public subnet 2 10.0.2.0/24 in AZ-2. Associate both with the public route table and enable auto-assign public IPv4.

        2 subnets · 2 AZs · no NAT Gateway

      3. 03

        Create security group

        p5-web-sg: inbound HTTP TCP 80 from 0.0.0.0/0, SSH TCP 22 from <MY-IP>/32.

        Security group

      4. 04

        Create target group

        p5-tg: target type Instances, protocol TCP, port 80, VPC p5-vpc, health check TCP. Register no targets yet — the ASG does that.

        Target group · TCP:80

      5. 05

        Create NLB

        p5-nlb: Network Load Balancer, internet-facing, IPv4, both public subnets. Listener TCP:80 forwarding to p5-tg.

        Network Load Balancer

      6. 06

        Create launch template

        p5-lt: Ubuntu 24.04 LTS AMI <YOUR-AMI-ID>, t3.micro, your key pair, p5-web-sg, public IP enabled, and the user-data script from scripts/deployment/user-data.sh.

        Launch template · User data

      7. 07

        Create Auto Scaling Group

        p5-asg from p5-lt, both public subnets. Capacity: min 2, desired 2, max 4.

        Auto Scaling Group

      8. 08

        Attach target group

        In the ASG's load balancing settings, attach p5-tg and turn on ELB health checks with a 120-second grace period.

        ASG ↔ Target group

      9. 09

        Launch EC2 instances

        The ASG launches two instances, one per AZ. User data installs Apache2, deploys the site and writes /instance.json. Wait for targets to become healthy.

        EC2 · Apache2

      10. 10

        Test NLB DNS

        Open http://<YOUR-NLB-DNS>, run the distribution test from the command line, then raise desired capacity to 3 and 4 to watch the ASG scale.

      local — aws cli v2
      # Target group (TCP:80, instance targets)
aws elbv2 create-target-group --name p5-tg \
  --protocol TCP --port 80 --target-type instance \
  --vpc-id <YOUR-VPC-ID> --health-check-protocol TCP

# Internet-facing Network Load Balancer in both public subnets
aws elbv2 create-load-balancer --name p5-nlb --type network \
  --scheme internet-facing --subnets <YOUR-SUBNET-1-ID> <YOUR-SUBNET-2-ID>

# Listener TCP:80 → target group
aws elbv2 create-listener --load-balancer-arn <YOUR-NLB-ARN> \
  --protocol TCP --port 80 \
  --default-actions Type=forward,TargetGroupArn=<YOUR-TARGET-GROUP-ARN>

# Auto Scaling Group (min 2 / desired 2 / max 4)
aws autoscaling create-auto-scaling-group --auto-scaling-group-name p5-asg \
  --launch-template LaunchTemplateName=p5-lt,Version='$Latest' \
  --min-size 2 --desired-capacity 2 --max-size 4 \
  --vpc-zone-identifier "<YOUR-SUBNET-1-ID>,<YOUR-SUBNET-2-ID>" \
  --target-group-arns <YOUR-TARGET-GROUP-ARN> \
  --health-check-type ELB --health-check-grace-period 120

      Full VPC, subnet, security group and launch template commands: scripts/deployment/aws-cli-reference.sh

      local — bash
      # Target health as the NLB sees it
aws elbv2 describe-target-health --target-group-arn <YOUR-TARGET-GROUP-ARN>

# 20 separate TCP connections → watch instance IDs alternate
for i in $(seq 1 20); do
  curl -s http://<YOUR-NLB-DNS>/instance.json; echo
done

# Demonstrate scaling by raising desired capacity
aws autoscaling set-desired-capacity \
  --auto-scaling-group-name p5-asg --desired-capacity 3

      09 Project summary

      Six services. One request path.

      Everything this project uses, what each part is responsible for, and what comes next.

      1. VPC

        Isolated network for the whole stack.

        10.0.0.0/16 with two public subnets across two AZs and an Internet Gateway.

      2. Security Groups

        Stateful firewall for the instances.

        Allows HTTP 80 from anywhere and SSH 22 from My IP only.

      3. NLB

        Distributes TCP traffic across healthy EC2 instances.

        Internet-facing entry point with a TCP:80 listener in both AZs.

      4. Target Group

        Tracks registered targets and their health.

        TCP:80 instance targets, health checked over TCP.

      5. EC2

        Runs the Apache web application.

        t3.micro · Ubuntu 24.04 LTS · Apache2 on port 80.

      6. Auto Scaling

        Maintains the required number of instances.

        Min 2 · desired 2 · max 4, replaces unhealthy instances.
